# 异文织机

一个无云服务、无外部数据库的本地 XML 多见证校勘工作台。TypeScript 服务端逻辑运行在 Vite 中间件中，浏览器界面提供导入、锚点对齐、交叠可视化、校勘单元、历史冲突、导出预检和往返核验。

## 运行

```bash
npm install
npm test -- --run
npm run dev -- --host 127.0.0.1 --port 5230 --strictPort
```

打开 <http://127.0.0.1:5230>，页面标题为“异文织机”。

## 数据与保真

- 原始 XML 原样写入 `data/raw/`，SHA-256 写入见证事件。
- 所有编辑以不可变事件 JSON 追加到 `data/events/`，重启后重建见证、锚点、单元、冲突和版本号。
- 删除见证只做逻辑删除；仍引用它的校勘单元会阻止删除并返回单元与片段清单。
- 正文视图是派生视图：空白和文本节点拼接保留，码位偏移以 Unicode code point 计算；自定义命名空间属性随源 XML 克隆。
- 未知元素不会被静默丢弃：导入后显示 XPath 式定位，导出预检返回阻断项，HTTP 导出以 422 拒绝。

## 校勘规则

- 同一见证的两个单元可交叉交叠，但锚点不允许错误地完整包含。
- 修订锚点会保留旧范围、修订原因和受影响单元 ID。
- 异序/倒置用多个 `seg` 的 `order` 与 `reversed` 表达；缺文、原文和编辑判断使用不同 `rdg@type`。
- 编辑请求带 `baseVersion`。陈旧提交不会覆盖新版本，服务记录包含双方范围和文本片段的冲突事件。

## 导出与往返

导出文件包含：

- `sources/source`：每个活动见证的完整源 XML 克隆。
- `apparatus/app/rdg`：校勘单元、见证、锚点、状态、录文、倒置片段和编辑判断。
- `sourceEvent` / `fragmentEvent`：把导出内容追溯到校勘或导出事件。

往返核验将差异分为：

1. `known-edit`：apparatus 等可追溯的已知编辑。
2. `lexical-only`：XML 声明、实体、属性书写等重新解析后语义相同的词法变化。
3. `unacceptable-loss`：文本、属性、元素或整个见证丢失等语义差异。

## 测试

`test/loom.test.ts` 覆盖命名空间与自定义属性、组合字符、跨元素范围、倒置片段、交叠/包含锚点、删除引用检查、版本恢复、并发冲突、未知节点导出拒绝和往返分类。
