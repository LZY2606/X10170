# 异文织机（Yiwen Zhiji）

本地运行的古籍异文校勘工作台：导入同一文本的多个 XML 见证本，按锚点并排阅读，
框选任意字符范围建立校勘单元，为每个见证记录原文、缺文、异序（倒置）或编辑判断。

不接云服务、不依赖外部数据库。原始 XML 逐字节保存在项目目录内；
页面所见的规范化文本永远是派生视图，不回写、不替换原文。

## 安装与运行

```bash
npm install
npm test -- --run
npm run dev -- --host 127.0.0.1 --port 5230 --strictPort
```

打开 <http://127.0.0.1:5230>，页面标题为「异文织机」。

## 数据位置

所有数据保存在工作目录的 `.loom-project/` 下：

- `state.json`：版本号、见证元数据、校勘单元、事件日志、元素策略
- `raw/<witnessId>.xml`：导入的原始 XML（与 sha256 校验，篡改即拒绝加载）
- `export.xml`：最近一次成功导出的带 apparatus 的 XML

删除该目录即得到全新空项目。

## 核心设计

- **保真 XML 词法器**（`src/core/xml.ts`）：手写解析器保留空白、注释、PI、CDATA、
  属性顺序、命名空间声明、命名/字符/自定义实体写法；`serialize(parseXml(xml)) === xml`。
- **规范化视图**（`src/core/normalize.ts`）：仅拼接文本（实体解码后）供展示，
  记录 规范化偏移→源节点 的映射；`pb`/`milestone` 成为非文本标记；
  锚点边界用 `Intl.Segmenter` 校验，不允许切断组合字符字形簇。
- **校勘模型**（`src/core/model.ts`）：同一见证内锚点允许真正交叉、禁止互相包含或完全相同；
  倒置异读由多个带 `order` 的片段表达，片段之间不得交叠。
- **修订与并发**（`src/core/store.ts`）：全项目单调 `revision`，每次提交 +1 并写事件；
  基于旧 revision 的提交得到 409 冲突，载荷包含双方范围与文本片段，绝不最后保存覆盖；
  锚点修订保留 before/after 与受影响单元；删除被引用见证时返回引用单元清单并拒绝。
- **导出与阻断**（`src/core/export.ts`）：默认安全映射 TEI 常见元素；
  未知元素、DOCTYPE/内部 DTD、非法锚点一律阻止导出，并给出见证、XPath 与原始偏移。
- **往返核验**（`src/core/roundtrip.ts`）：原始 XML → 导出 XML → 重新解析，
  用 LCS 做语义树对齐，差异分为「已知编辑 / 仅词法变化 / 不可接受丢失」，
  每项差异可下钻到编辑事件；无事件支撑的丢失即判不可接受。

## 页面

- 见证导入：粘贴 XML、查看原文、删除前引用检查
- 锚点对齐：多见证并排、点首尾框选、跨元素范围、建立单元与异读
- 交叠区间：颜色叠加 + 金色虚线标交叉、表格判定交叉/错误包含
- 校勘单元：异读列表、锚点修订、删除
- 版本历史：事件流、before/after、受影响单元
- 导出预检：阻断项定位、登记 keep/unwrap 策略、生成 XML
- 往返核验：三分类差异报告与事件追踪

## 测试

`tests/` 共 27 个用例，覆盖：命名空间与属性序、实体写法、组合字符、
跨元素范围、页码标记、倒置片段、交叠/包含校验、并发 409、删除保护、
锚点修订历史、持久化与篡改检测、未知节点拒绝导出、往返三分类。
